# RootSleuth 运营控制台常见问题 FAQ

[English](CONSOLE_FAQ.en.md) | 简体中文

**Q1：为什么不能审批自己发起的申请？**
系统强制禁止自审（申请人 == 当前操作人时返回 403）。变更必须由同层级及以上的其他角色独立复核，保证可追溯与制衡。

**Q2：新建案例还需要自己编案例 ID 吗？**
不需要。提交后由后端自动生成 `KB-YYYYMMDD-NNN` 格式的唯一 ID：日期取 UTC 当日，序号按「已入库案例 + 在途新建变更集」去重后取最小空位，因此审批在途期间重复提交也不会冲突。创建成功的提示与审批单内容中均可见该 ID。

**Q3：审批通过后知识什么时候生效？**
终审通过即写入新版本快照并失效语义缓存（审计动作 `semantic_cache_invalidate`），流水线下一次检索即使用新知识，无需重启服务。

**Q4：AI 诊断显示「降级」怎么办？**
查看详情中的降级原因：
- `llm_timeout`：在配置中心调大 `llm_timeout_seconds`（默认 45，上限 300）。
- `invalid_json`：模型输出偶发不合法，重新点击诊断即可。
- RAG 无召回（unknown）：建议把该类告警沉淀为新知识案例。

**Q5：拒绝后变更去哪了？**
变更集状态置为 `rejected`，不会发布内容；可在知识库「变更记录」中查看其 diff 与理由，修改后可重新提交。

**Q6：回滚会丢历史版本吗？**
不会。知识案例回滚是「读取目标版本快照 → 生成新版本」，规则回滚是「目标版本重新激活、当前激活版本标记已替代」，全部历史可追溯。

**Q7：如何切换审批模式？**
sys_admin 在「审计与配置 → 配置中心」修改 `approval_mode`（OFF / SINGLE_REVIEW / MULTI_LEVEL），立即生效并写审计。已在途的审批单按创建时的步骤数继续流转。

**Q8：「待我审批」列表里为什么看不到某张单？**
常见原因：① 你是该单申请人（禁止自审）；② 当前审批步骤要求的角色高于你的角色；③ 该步骤已被处理或审批单已不是待审状态。

**Q9：未知模板晋升出的规则分值是多少？**
固定 `score: 0.6`、`severity: warning`，关键词取模板中的英文 token（最多 6 个）。晋升后可在规则管理中调整并重新发布。

**Q10：预览环境的演示账号有哪些？**
- `demo-operator@atoms.dev` → 值班运维（可诊断、反馈）
- `demo-sre@atoms.dev` → SRE（可编辑知识库、发起审批）
- `demo-lead@atoms.dev` → 审批人（可审批）
- `demo-admin@atoms.dev` → 系统管理员（规则发布、配置中心）

**Q11：合并提案里「主案例」和「冗余案例」是什么关系？**
主案例合并后保留并继续接收反馈，冗余案例被归档（`archived`，不再参与 RAG 召回）。系统默认建议反馈分最高的案例作为主案例。

**Q12：审批单上「风险等级」是怎么定的？**
知识库变更中修改 `root_cause` 或 `solution` 时为 medium，其余为 low；合并与模板晋升固定为 medium。
